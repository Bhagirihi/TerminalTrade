# TerminalTrade V3

Blank branch — V3 starts here.

## Modules

- `npm run login` — Upstox login (OAuth, token into `.env`).
- `npm run start` — check the token, ask to log in again if expired, show Upstox funds + live NIFTY/BANKNIFTY, ask "Do you want Live trading?" (YES = real orders, NO = paper), ask your trading budget for the day, then WATCH the market live. Prices are REALTIME via Upstox's websocket feed (v3): index levels, open-position P&L and SL/T2 exits update on the tick that crosses the level. Candles still refresh every 30s — entries are evaluated only when a new 5m bar closes, which is the correct time to act. If the feed drops, the loop falls back to REST polling and keeps working. Live entries are market BUY + a broker SL-M at the stop; the loop exits at T2 or 15:15, and the broker SL-M owns the stop. Ctrl+C stops and squares off. `npm run start -- --once` does one pass and exits. First run after pulling: `npm install` (adds the `ws` websocket library).
- The score's liquidity check (5 points) is now measured, not guessed: the loop subscribes to the ATM ± 1 strike CE/PE keys (real numeric tokens from the contracts API) so the feed's bid/ask is warm before a setup appears, and a spread of 0.5% of mid or tighter passes. No quote yet (feed down, or the band still warming up on the first tick) scores as 'nodata' — the score ceiling is 90 with liquidity measured, 85 without it, and volume stays nodata (index candles carry no volume).
- The funds line carries the day's trade fund: `Upstox funds — available ₹15,510.40 · used ₹0.00 · total ₹15,510.40 · trade fund ₹12,000.00` (omitted when the budget is uncapped). Ctrl+C stops cleanly: the first press squares off and exits (the 30s sleep is woken, not just cleared), a second press force-quits at once, and a 20s safety net exits even if a tick or square-off is stuck.
- Budget recycles on close: when a position closes (SL/T2/SL-M/15:15), its net proceeds — entry cost + net P&L, i.e. the exit value minus charges — go back into the day's budget, so the loop can trade again. `spent + left` always equals the budget; a win can push the leftover above the budget, which is real profit. Each position is credited exactly once.
- Daily trade record: every day's trades are stored in `daily/<YYYY-MM-DD>.json` (local only, gitignored) — each trade with entry/exit datetimes, strike, expiry, side, qty, lots, SL/T1/T2, exit reason, gross/charges/net, plus a summary with the day's realised P&L split by paper/live. Written when a trade opens, when it closes, and once more when the loop ends; `npm run paper` refreshes it for any day it reconciles. The record also carries the day's mode and budget, so a restart resumes the session (see below).
- Screen layout: on the terminal, today's open positions sit in their own box (titled with the count and mode, e.g. `OPEN POSITIONS (1) · PAPER`), each row carrying its entry date and time (`PAPER NIFTY 25900 CE · 27 Nov 09:05 — 1 lot @ ₹195.85, ...`); only OPEN rows show — a closed trade is dropped from the box the moment it closes instead of lingering with a phantom live P&L. A blank line below it the log sits in its own box. The log file stays plain lines — no boxes there.
- Resume: restarting `npm run start` mid-day continues the day instead of resetting it — mode and budget come from the day's stored record, spent/left are rebuilt from the ledgers (open trades at full entry cost, closed trades at their realised loss or minus their win, expired trades at full cost), and every contract traded today, open or closed, stays in the traded-today list so the loop can never re-enter one. A restart prints `Resuming today's <MODE> session — budget ₹X, spent ₹Y, left ₹Z, N trade(s) today (M open)` and asks nothing. On a fresh day with no session stored yet, the most recent earlier day's mode and budget carry forward (the log names the source day, e.g. `carried forward from 2026-11-26`), so the morning is just the login. `npm run start -- --fresh` ignores the stored session and asks the mode and budget again.
- Running on the server, no terminal needed: the loop can run the whole session (09:00–15:30 IST) as a background service. One-time setup on the server after pulling: `bash tools/install-service.sh` (installs a weekday cron that calls the watchdog every 5 minutes). The morning routine stays: log in once (`npm run login`) so a fresh token is in `.env` — the login still needs a human in a browser. After that the watchdog starts the loop on its own around 09:00, restarts it if it ever dies mid-day, and does nothing after 15:30 or on weekends. The loop runs as `npm run service` (`node tools/start.js --service`): it never prompts — if the token is dead it logs the fact and exits (the watchdog retries every 5 min, so it starts by itself once you log in), and it starts a fresh day with the last day's mode and budget carried forward, so no interactive run is needed at all. Only one loop ever runs at a time: a lock file (`v3-loop.lock`, gitignored) refuses a second start, and a lock whose pid is dead is stale and taken over. Logs land in `logs/v3-<date>.log`; `bash tools/v3-service.sh status` shows whether it is running plus the tail of today's log, and `bash tools/v3-service.sh stop` stops it (SIGTERM — it squares off first).
- Live indicator preview: each card carries a `LIVE forming bar` line — VWAP, EMA 20/50, RSI, MACD, ADX and ATR% recomputed on the forming 5m bar (live LTP as its close, refreshed from REST every 30s and moved tick-by-tick by the feed), so you see the checks and the ADX moving as the price moves. It is display only and marked "not a signal": entries still fire only on a closed 5m bar, so a setup can never appear and vanish inside a bar. The card title's regime/ADX still comes from the closed bars.
- `npm run paper` — reconcile the paper ledger against live option prices: closes trades at SL/T2, shows live P&L on open ones, all net of charges.
- `src/indicators.js` — VWAP, EMA 20/50, RSI 14, MACD 12/26/9, Volume MA 20 (+ ATR, ADX).
- `src/entry-rules.js` — CE/PE setups from the screenshot plan, on 5m candles.
- `src/trade-score.js` — 0–100 trade quality calculator (pass bar 70).
- `src/regime.js` — rule-based regime label (trending/sideways × high/low vol); XGBoost-ready features, no model trained yet.
- `examples/run-rules.js` — run the rules: `node examples/run-rules.js` (demo candles) or `--candles5m 5m.json --candles15m 15m.json` with your own candles.
